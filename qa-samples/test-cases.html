Sample from my own project, Project Manager. Not client work.My paid QA work is confidential, so these samples use a web app I built and test myself. The commits and test names below can be checked in the repository; where I took a measurement myself, the page says how.

Test cases: offline sync and roles

25 cases for Project Manager v2 across sign-in and sign-out, the Kanban board with role permissions, offline editing and sync, two-person conflicts, notifications and responsive layout. 21 are covered by an automated test that I link to; 4 are manual. 11 are negative or permission-refusal cases. Part of the test plan.

How to read this

  • Automated rows link to the real spec on GitHub (branch v2-supabase) and quote the test title. The expected result in those rows is what that test asserts, in plain words. The suites need the local Supabase stack and were not run again while writing this page.
  • Priority is my own: P1 = data integrity, permissions or sign-in; P2 = core behaviour; P3 = polish.
  • Test data. Local seed users (admin, manager, developer, designer, tester, IronWarrior), each with a local-only password from the seed file. In Website Redesign: admin owner, manager manager, designer and developer members, tester viewer. Designer is not a member of Internal Wiki.
  • Where a gap exists in automation, the last column says so.
